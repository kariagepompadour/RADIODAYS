# Wi-Fiのない環境での利用：USB接続の調査と設計提案

- 作成日：2026-10-21
- 状態：**調査と提案のみ。コードは作っていない**
- 前提：職場のMacは有線LANでインターネットにつながっている。Wi-Fiは使えない。Cardputer ADVはMacにUSBでつながる
- **続き（2026-10-21）**：KariPomとの比較と、USBシリアル中継の詳しい設計は [usb-relay-design.md](usb-relay-design.md)

印：【確認】このMacの開発環境やソースで確かめた／【一般】一般に知られている情報で、この環境では確かめていない／【未確認】実機で試す必要がある

## 1. 結論

| 方式 | 一言で | 職場での現実性 |
| --- | --- | --- |
| ① USBネットワーク（CDC-NCM） | Cardputerを「USBのLANアダプター」としてMacにつなぎ、Macのインターネット共有で通信する | ESP32-S3側の部品は揃っているが、**つなぐためのプログラムは自作が必要**。Mac側で**インターネット共有**（管理者権限）が必要で、職場の規則で使えない可能性が高い |
| **② USBシリアルでMP3を中継（推奨）** | Macが放送を受信し、MP3のデータをUSBシリアルでCardputerに送る | **Macの通常のネット接続（プロキシを含む）をそのまま使う**。管理者権限も共有設定も要らない。必要なのはMacで動かす小さなスクリプトだけ。Cardputer側の変更も小さい |
| ③-a Macを無線の親機にする（インターネット共有でWi-Fiへ） | コードの変更なし | 管理者権限が必要。社内ネットワークに無線の出入口を作ることになり、**多くの職場で禁止**されている |
| ③-b スマートフォンのテザリング | コードの変更なし | すぐ使える。モバイル通信を使う（128kbpsで1時間に約58MB） |

**提案**：職場では **② シリアル中継** がいちばん現実的。③-bは今日からでも使える代わりの方法。①はUSBを挿すだけで使える体験としては理想的だが、作るのが難しく、Macの設定と職場の規則の壁が大きい。

## 2. 共通の確認事項

| 項目 | 結果 |
| --- | --- |
| Cardputer ADVのUSB-C端子 | ESP32-S3のUSB（OTGとUSB-Serial-JTAGの両方に使える端子）につながっている【確認：Media JogがこのポートでUSB HIDとして動いている】 |
| 速さ | USB 2.0 Full Speed（12 Mbps）。128 kbpsのMP3に対して十分に速い【一般】 |
| 今のRADIO DAYSのUSB設定 | 「Hardware CDC and JTAG」（USB-Serial-JTAG）。シリアルの記録（ログ）だけに使っている【確認】 |

## 3. 方式① USBネットワーク（CDC-NCM）

### ESP32-S3とArduino環境に「あるもの」と「ないもの」

| 項目 | 結果 |
| --- | --- |
| TinyUSBのNCM（USBネットワーク）ドライバー | **組み込み済み**。ボードパッケージ m5stack:esp32 3.3.9 の設定で `CONFIG_TINYUSB_NCM_ENABLED=y`、ライブラリに `ncm_device.c.obj`（`netd_init`、`tud_network_xmit` など）がある【確認】 |
| Arduinoコア | NCM用のコールバック（`tud_network_recv_cb` など）が「中身のない仮の関数」として置かれている。自作の記述子は `USB_INTERFACE_CUSTOM` で登録できる【確認：`esp32-hal-tinyusb.c`・`.h`】 |
| Arduinoから使う部品 | **ない**。USBNCMのようなクラス、ネットワーク（lwIP・esp_netif）とつなぐ部分、使用例はArduino側にない【確認：USBライブラリの一覧】 |
| ESP-IDF | NCMの使用例がある（`tinyusb` のNCM、`sta2eth` など）【一般・未確認】。ArduinoのUSBの仕組みと組み合わせられるかは【未確認】 |

→ **ESP32-S3側に機能は存在するが、Arduinoでそのまま使える形にはなっていない。** USBの記述子、受信と送信のつなぎ込み、ネットワークのインターフェースの作成（DHCPを含む）を自作する必要がある。

### macOS側

| 項目 | 内容 |
| --- | --- |
| ドライバー | macOSはUSBのCDC-ECM・CDC-NCMを、追加のドライバーなしで扱えるとされる【一般・未確認】。RNDISは標準では扱えない |
| インターネットの共有 | 「システム設定 → 一般 → 共有 → インターネット共有」で、有線LANの接続をUSBのネットワークへ共有する必要がある【一般】。**管理者権限が必要**。会社の管理（MDM）で無効にされていることが多い |
| 共有の対象に出るか | Cardputerのインターフェースが共有先の一覧に出るかは【未確認】 |

### そのほか

| 項目 | 内容 |
| --- | --- |
| USBの設定 | 「USB-OTG（TinyUSB）」に変える必要がある。アプリが約53KB大きくなり（Stage 2-0の実測）、0x150000を超える。Launcherは大きさに合わせて領域を作るので、導入自体はできる見込み |
| シリアルの記録 | TinyUSBのCDCと同時に使える（NCMとCDCの複合デバイス）【一般】 |
| 書き込み | ダウンロードモードへの自動切り替えは使えなくなり、G0を押しながら電源を入れる手順になる（Media Jogと同じ）。Launcherからの導入には影響しない |
| Wi-Fiとの自動切り替え | USBとWi-Fiの2つの経路を持てる。どちらを使うかの切り替えを作る必要がある |
| 難しさ | **高い** |

## 4. 方式② USBシリアルでMP3を中継（推奨）

### しくみ

```text
放送局 ──(インターネット、社内のプロキシ)── Mac：curlで受信
                                             │ MP3のデータをそのまま
                                             ▼
                              USBシリアル（/dev/cu.usbmodem…）
                                             ▼
               Cardputer：シリアルから読む → 今のMP3デコーダー → スピーカー
```

### Mac側

- **新しいソフトのインストールは不要。** macOSに最初から入っている `zsh`・`curl`・`stty` で書ける、短いスクリプトを1本使う【一般】
- スクリプトの仕事：
  1. Cardputerから「局番号」を受け取る
  2. 同じスクリプトの中にある局の一覧からURLを選ぶ
  3. `curl` で受信してシリアルに流す
  4. 局が変わったら、今の受信を止めて次の局を受信する
- **安全のため、CardputerからURLやコマンドを受け取らず、番号だけを受け取る**（スクリプトの中で決めた一覧以外にはアクセスしない）
- スクリプトを動かしている間は、Macを起こしておく必要がある

### Cardputer側

| 項目 | 内容 |
| --- | --- |
| 変更 | シリアルから読む「音声の入口」を1つ追加する。デコーダー、スピーカー、ノイズ、メーター、選局は今のものを使える |
| USBの設定 | 今のまま（Hardware CDC and JTAG）。アプリの大きさもほとんど変わらない |
| シリアルの記録 | 共存できる。Cardputer→Macは記録と局番号、Mac→CardputerはMP3。スクリプトは、決まった印で始まる行だけを局番号として読む |
| 速さと流れの調整 | 必要なのは約16KB/秒。USBのシリアルは、受け手のバッファーがいっぱいになると送り手が待つので、自然に速さがそろう【一般】。受信バッファーは大きめに設定する（Launcherも8KBにしている【確認】） |
| 再生の安定性 | USBは途切れにくく、Wi-Fiより安定する見込み【推測】。今の32KBのストリーム用バッファーをそのまま使う |
| 曲名 | `curl` が受信するときに曲名の情報を要求しないので、曲名は出ない（工夫すれば出せる） |
| Wi-Fiとの切り替え | スクリプトからの「はじめまして」の合図があれば中継、なければWi-Fi、という自動判定ができる |
| おまけ | Macが受信するので、**HTTPSの放送局も聴ける**（Cardputer単体では聴けない局が増える） |
| Launcher | 影響なし（同じapp-onlyのバイナリ） |
| 難しさ | **低〜中** |

## 5. 方式③ その他

| 方式 | 内容 | 注意 |
| --- | --- | --- |
| ③-a Macのインターネット共有で、MacをWi-Fiの親機にする | 「インターネット共有」で有線LANの接続を「Wi-Fi」に共有すると、Macが無線の親機になる。RADIO DAYSは今のままWi-Fiでつなぐだけ【一般】 | 管理者権限が必要。社内ネットワークに無線の出入口を作るため、**情報システム部門の許可なしに行うべきではない** |
| ③-b スマートフォンのテザリング | スマートフォンの「インターネット共有」にWi-Fiでつなぐ。コードの変更なし | モバイル通信の量。職場で私物のテザリングが許されているかを確認 |
| ③-c 有線LAN→Wi-Fiの小型ルーター | 有線LANにつないで、無線を出す | 社内ネットワークに機器をつなぐことになり、規則で禁止されていることが多い |

## 6. 職場のネットワークで気をつけること

| 項目 | 内容 |
| --- | --- |
| プロキシ | 社内ではプロキシ経由でしか外に出られないことがある。**②は `curl` がプロキシを使える**（`https_proxy` などの設定。macOSのシステム設定のプロキシを自動では使わない点に注意）。①と③-aのNAT経由の通信は、プロキシを通らないため遮断される可能性がある |
| ポート番号 | 多くの放送局は80番以外（8000、8040、2020、8062、8025など）で配信している。社内の防火壁で遮断されることがある。②でも同じ |
| 規則 | 業務中の音声配信の利用、通信量、私物の機器の接続について、職場の規則を確認する |
| 共有と無線の出入口 | ①と③-aは、ネットワークの構成を変える操作になる。必ず事前に許可を得る |
| Cardputerからの指示 | ②では、MacはCardputerから任意の指示を受け取らない作りにする（局番号だけ） |
