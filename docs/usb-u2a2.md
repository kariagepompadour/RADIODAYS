- 作成日：2026-10-21

## 1. U2aの実機試験の結果（作者、2026-10-21）

| 項目 | 結果 |
| --- | --- |
| 環境 | 職場のMac（USB）、湘南ビーチFM（80.4MHz）。Cardputer自身はWi-Fiにつながらない |
| USB中継での再生 | **音が出た**（基本的な中継は実機で確認） |
| 音切れ | 「プツッ」という短い途切れが何度も。`buf` が99%→0%→4%→0%→1%と上下し、Macの送信は6〜19KB/秒で変動。10:20:40ごろから減り、`buf` は99%付近で安定 |
| 通信停止 | 約7分後、Macの送信が15.7KB/秒→6.1KB/秒→0KB/秒と急に止まった。Cardputerは `WAITING FOR WI-FI/USB`、`LINK L0`。画面とノブは動く（フリーズではない） |
| Macのスクリプトの再起動 | ポートは開けたが、HELLOが届かず、つながらなかった |
| Wi-Fi | USBで再生中も、家のアクセスポイントへの接続を繰り返していた（`[WIFI] connecting` → `timeout, retry in 60 s`） |

## 2. 調査：通信が止まり、戻らなかった問題

**音切れとは分けて調べた。**

### 2.1 確認できたこと（コードとシミュレーション）

| 事実 | 根拠 |
| --- | --- |
| U2aのリンクは、USBの「接続」信号（`Serial.isPlugged()`）が1秒続けてfalseになると、**すぐにL0になる**。しかもL0では、この信号がfalseの間、**HELLOを1回も送らない** | U2aの `radiodays_link.h`（`service()` の最初の部分）。設計で「USBが抜けた」と判断するために入れた |
| `isPlugged()` は、USBの通信そのものではなく、**ホストからの1ミリ秒ごとの合図（SOF）を、FreeRTOSの時刻の割り込みで見張った結果**。Arduinoコアのコメントにも「健全な接続でも一時的にfalseになる」とある | Arduinoコア3.3.9の `HWCDC.h` 73〜77行、`HWCDC.cpp` 140〜147行、ESP-IDFの `usb_serial_jtag.h` の説明 |
| シミュレーションで、Macのスクリプトが動いたまま信号だけをfalseにすると、**U2aはL0になり、HELLOを0回しか送らず、そのまま戻らない** | `sim2/run_sim.sh --old` の結果（第6節） |

### 2.2 実機の記録との対応

| 実機の様子 | U2aの「信号がfalse」による説明 |
| --- | --- |
| 送信が数秒で急に0になった（徐々にではない） | L0に落ちた瞬間に、Cardputerはクレジットを出さなくなる。Macは残りのクレジットを送り切って止まる |
| `LINK L0` になり、そのまま | 信号がfalseの間、HELLOを送らないので、L0から出られない |
| Macのスクリプトを起動し直しても、HELLOが届かない | Cardputerが**送っていない**。Macの受信の問題ではない |
| 画面とノブは動く | リンクの処理は動いている。止まっているのはHELLOの送信だけ |

**確認してほしいこと**：`LINK L0` という文字は、Cardputerの画面には出ない。Macのターミナルに出る `Cardputer> [STAT] … link L0 …` の行だけにある。もしターミナルでこの行を見たのなら、**L0の間もCardputerからMacへの送信は動いていた**ことになる。その場合、「HELLOを送っていない」ことがはっきりする。

### 2.3 まだ仮説にとどまること

- 実機で、なぜ `isPlugged()` が長くfalseになったのか（Wi-Fiの接続の試み、macOSのUSBの省電力、など）。**わかっていない**。U2a2では、この信号でリンクの状態を変えないので、理由が何であっても止まらない。かわりに、信号がfalseになった回数を記録する（`[DIAG] … unplugged N`）
- Cardputerを再起動すれば戻ったか（未確認）

### 2.4 修正（U2a2）

| 修正 | 内容 |
| --- | --- |
| `isPlugged()` は記録だけ | どの状態でも、この信号で状態を変えない。**L0では常に2秒ごとにHELLOを送る**（U1と同じ） |
| ケーブルを抜いたときの判断 | タイムアウトだけで判断する（受信中5秒→L1、待機中6秒→L0、選局中12秒→L0）。U2aの1秒より遅くなる |

## 3. 調査：音切れ

### 3.1 確認できたこと

| 事実 | 根拠 |
| --- | --- |
| `buf 0%` はストリーム用バッファー（32KB）が空ということ。**デコーダーにデータが届くのが間に合っていない**（デコーダーが遅いなら、バッファーは満杯になる） | 再生用タスクのコード。`buf` は `bufferPercent` |
| データの供給を止めうるのは、(a) 放送局とMacのネットワーク、(b) Cardputerのクレジット、の2つ | やり取りの設計 |
| **U2aには、(b) を壊す欠陥がある。** Cardputerからの行は、HWCDCの書き込み（タイムアウト0）で、**丸ごと失われる**（ほかのタスクが書いている最中）か、**途中で切れる**（送信バッファーが満杯）ことがある。U2aでは、MOREの行が1つ失われると、Cardputerは「Macにクレジットを渡した」と思い込み、Macは知らないままになる。この差は二度と埋まらない。しかもU2aは、空きをまとめて1行（最大14,336バイト）で出すので、**1行失うだけで、ほぼ全部のクレジットが消える** | Arduinoコアの `HWCDC::write()`（544行：ロックが取れなければ0バイト、553〜600行：満杯なら途中まで）、U2aの `credit()` |
| シミュレーションで、Cardputerの行の3%を失い2%を切ると、**U2aは90秒の間に再生が止まった（失われた行は6行だけ）** | `sim2/run_sim.sh --old`（第6節） |
| U1は、MOREを常に2KBずつ出していた（1行失っても2KB分）。U1はWi-Fiを使わない。局も違った（Radio Paradise） | U1のコード、`usb-u1.md` |

### 3.2 まだ仮説にとどまること

| 仮説 | 内容 | 確かめ方（U2a2で追加） |
| --- | --- | --- |
| 失われたMOREで、クレジットが足りなくなった | 上の欠陥。実機で行が失われたかは記録がない | `[DIAG] … tx-fail N`（書けなかった行の数）、`credit-resent` |
| 放送局やネットワークが遅かった | 湘南ビーチFMの職場からの受信が不安定だった可能性。10:20:40以降に安定したことも、これで説明できる | Macの `[relay]` 行の「station … KB/s」「waiting for the station …%」 |
| Wi-Fiの接続の試みが邪魔をした | 試みの間隔は5→10→20→40→60秒と広がる。音切れが2〜3分後に減ったことと合う。ただし、仕組みは確かめていない（Wi-Fiのタスクは、再生用タスクと同じコア0で、優先度が高い） | `[DIAG] … gap-decode`（デコーダーが止まった最長時間）、`gap-loop`、`gap-link` |
| ループが止まって、クレジットが遅れた | 描画などでループが長く止まれば、クレジットも止まる | `[DIAG] … gap-link` |

**今回の記録だけでは、どれが原因かを決められない。** U2a2では、次の実機試験で区別できるように、記録を加えた（第4節）。

### 3.3 修正（U2a2）

| 修正 | 内容 |
| --- | --- |
| **クレジットを「合計」で送る** | `@RD CREDIT <id> <合計>`。Cardputerは「この局で、これまでに許可した合計」を送る。Macは「合計−送った量」だけ送ってよい。**行が失われても、次の行がすべてを伝える**。クレジットが残っているのに新しい許可がない間は、0.5秒ごとに同じ合計を送り直す |
| 安全は同じ | Macは、最新の合計を超えて送らない。Cardputerは、受信キューに入りきる分しか合計を増やさない（U1の式のまま）。古いidや古い合計（増えていない値）は無視する |
| 書けなかったTUNE | 書けなかったら、次の回にもう一度書く。返事がなければ、3秒ごとに同じidで送る（12秒まで）。Macは同じidのTUNEを無視する |
| Wi-Fiの接続の試み | 中継がつながっている間は試みない（第5節） |

## 4. 追加した記録（次の実機試験のため）

### 4.1 Cardputer（10秒ごと。Macのターミナルに `Cardputer> [DIAG] …` と出る）

| 項目 | 意味 |
| --- | --- |
| `link L…` | リンクの状態（0：中継なし、1：待機、2：選局中、3：受信中） |
| `q-max` | 受信キューの最大（バイト） |
| `in-flight` | 許可したが、まだ届いていない量 |
| `hello` | 送ったHELLOの数（L0で増えるはず） |
| `tx-fail` | 書けなかった行の数（HWCDCが忙しい、または満杯） |
| `credit-resent` | クレジットの合計を送り直した回数 |
| `unplugged` | `isPlugged()` がfalseになった回数（状態は変えない） |
| `to-L0` | L0に落ちた回数 |
| `gap-link`／`gap-loop`／`gap-decode` | リンクの処理、ループ、デコーダーが止まった最長時間（ミリ秒） |
| `underruns` | 再生中にバッファーが1/8を切った回数（起動からの合計） |

画面の最下行は、ラジオの画面で `I` を押すと、記録の要約に切り替わる：`L3 Q12K F2K UR0 TX0 PL0 G45`（状態、キュー、届いていない量、underruns、書けなかった行、信号がfalseになった回数、最長のループの止まり）。もう一度 `I` で元に戻る。

### 4.2 Mac（10秒ごと）

```text
[relay] station 15.9 KB/s, to Cardputer 15.8 KB/s, waiting for credit 3%, for the station 85%, lines from Cardputer 31 (HELLO 0), bytes 1022
```

| 項目 | 意味 |
| --- | --- |
| `station` | 放送局から受け取った速さ |
| `to Cardputer` | Cardputerへ送った速さ |
| `waiting for credit` | 送るデータはあるのに、Cardputerの許可を待っていた時間の割合（高ければCardputer側が律速） |
| `for the station` | 許可はあるのに、放送局からのデータを待っていた時間の割合（高ければ局・ネットワークが律速） |
| `lines from Cardputer`、`HELLO`、`bytes` | Cardputerから届いた行・HELLO・バイト数。**0なら、Cardputerから何も届いていない** |

さらに、Cardputerから10秒間何も届かなければ「Nothing at all from the Cardputer for 10 s」と出る。HELLOは、届くたびに表示する。

## 5. Wi-Fiの接続の試み

| 項目 | 内容 |
| --- | --- |
| U2aの動き | 中継で再生中も、保存したアクセスポイントへの接続を、5〜60秒おきに20秒ずつ試していた（Stage 3-3のまま） |
| U2a2 | **中継がつながっている間（L1〜L3）は、接続を試みない**（`[WIFI] paused: the USB relay is in use`）。すでにWi-Fiにつながっている場合は、そのままにする |
| 中継がなくなったとき | すぐに試みを再開する（`[WIFI] resumed: no USB relay`）。**家などWi-Fiだけの場所では、Stage 3-3と同じ動き**（中継が一度もつながらないので、試みは止まらない） |
| U2bとの違い | 再生中にWi-FiとUSBを切り替える機能は作っていない（U2b） |
| 音切れとの関係 | **まだ断定していない**（第3.2節）。止めたのは、職場では不要で、影響の可能性を減らすため |

## 6. シミュレーション（2026-10-21）

```bash
sh tools/usb-relay/sim2/run_sim.sh             # U2a2：全項目
sh tools/usb-relay/sim2/run_sim.sh --negative  # U2a2：確認用（あふれを検出すること）
sh tools/usb-relay/sim2/run_sim.sh --old       # U2a：実機の症状が再現するか（比較用）
```

`sim2` は、U2aの `sim` に次を加えたもの（`sim` はU2aの記録のため、そのまま残した）。

- 障害の注入：Cardputerの行を失う・途中で切る、`isPlugged()` だけをfalseにする、ケーブルを抜く（両方向とも何も通らない）、TUNEの行を失う、Macのスクリプトを止めて起動し直す
- デコーダーの代わり：32KBのバッファーを16KB/秒で消費し、ファームウェアと同じく1/8を切ったらunderrunとして3/4まで貯め直す

### 6.1 U2a（比較用）：実機の症状は再現したか

| 試験 | 結果 |
| --- | --- |
| 90秒の再生中、行の3%を失い2%を切る | **再生が止まった**（失われた行は6行。underrun 1回）。**再現した** |
| Macのスクリプトは動いたまま、`isPlugged()` だけを11秒falseにする | **L0になり、HELLOは0回、最後までL0**。**再現した** |

どちらも、実機で見えた症状（急に止まる、L0から戻らない）と同じ形になった。**ただし、実機で実際にこれが起きたことの証明ではない。**

### 6.2 U2a2：結果

**41項目すべて合格**（下の「試験の直し」を参照）。

| 分類 | 内容 |
| --- | --- |
| U2aからの回帰試験（37項目） | 混入なし、分割受信、偽の返事、選局の連続、許可ホストとポート、切断とタイムアウトなど、U2aと同じ試験。クレジットの試験は合計方式に合わせた（古いidの合計、切れた行、U2aのMORE、増えていない合計を無視） |
| **行を失う・切る（120秒）** | 3%を失い2%を切っても、**止まらない**。underrun 0、あふれ0 |
| **`isPlugged()` だけがfalse（6秒）** | **影響なし**（L3のまま、underrun 0） |
| **Macのスクリプトを止める→起動し直す** | L3→L1→L0。**L0の間、2秒ごとにHELLO**（`isPlugged()` がfalseでも）。起動し直すと、つながって再生 |
| **TUNEの行が失われる** | 3秒後に送り直して受信 |
| **バッファーの枯渇と再充填** | 局が遅い（12KB/秒）とunderrunと再充填が起き、Macの `[relay]` 行は「waiting for the station 100%」。Cardputerが読まない間は「waiting for credit 63%」。読み始めるとunderrunなしで再生 |
| 全体 | 受信キューのあふれ0、同時に読むのは常に1つ |
| 確認用（`--negative`） | キューを超えるクレジットで、883,616バイトのあふれを検出 |

**試験の直し**：途中の実行で2つ見つかった。

1. **U2a2の不具合（修正済み）**：TUNEの送り直しのために、URLを300文字の入れ物に写していた。そのため、300文字を超えるURLが切り詰められ、Macに「正しいURL」として届いてしまった（MacはURLではなくHTTPの理由で拒否した）。写さずに、局の一覧の文字列をそのまま使うように直した
2. **試験の誤り**：Macのスクリプトを止めた後、試験側が読むのをやめていた。キューが満杯のままなので、Cardputerは「止まった」と判断しない（設計どおり。再生の一時停止は通信の停止ではない）。実機と同じく読み続けるように直した

**シミュレーションでわからないこと**：実機の `isPlugged()` がなぜfalseになるか、実機のHWCDCで行がどれだけ失われるか、職場のネットワーク、Wi-Fiの影響、本物の音。

| `tools/usb-relay/RadioDaysRelay_U2a2.command` | U2a2用の中継（合計のクレジット、同じidのTUNEを無視、`[relay]` の記録） |
| `tools/usb-relay/sim2/` | U2a2のシミュレーション（障害の注入、U2aとの比較） |
| `docs/usb-u2a2.md`、`docs/images/ufo-orbit-preview-u2a2.png` | この資料と、UFOの軌道の図 |

**U2a2のCardputerには `RadioDaysRelay_U2a2.command` を使う。** U2aのスクリプトとは組み合わせられない（スクリプトが「This Cardputer runs RADIO DAYS U2a2 …」と知らせる）。

## 10. 実機で確かめる手順

### 準備

1. Launcherで `firmware/RadioDays_U2a2/RadioDays_U2a2.ino.bin` を入れる（「Need …」が出たら「Cancel」）。起動画面の右上が「U2a2」
2. 職場のMacに `tools/usb-relay/RadioDaysRelay_U2a2.command` をコピーする
3. ターミナルの記録を保存できるようにしておく（終わったら、ターミナルの「シェル」→「テキストとして書き出す」）

### 手順1：音切れ（U2aと同じ条件）

1. 湘南ビーチFM（80.4MHz）を、**15分以上**再生する
2. ラジオの画面で `I` を押し、最下行の `UR`（underruns）と `TX`（書けなかった行）を見る
3. ターミナルの `[relay]` と `Cardputer> [DIAG]` の行を保存する
4. 余裕があれば、同じことをRadio Paradise（U1で安定した局）でも行う

| 見ること | 読み方 |
| --- | --- |
| 音切れのとき、`[relay]` の「for the station」が高い | 局・ネットワークが律速 |
| 音切れのとき、「waiting for credit」が高く、`[DIAG]` の `gap-link` や `gap-loop` が大きい | Cardputerの処理が遅れた |
| `gap-decode` が大きい | デコーダーが止められた |
| `tx-fail` が増えている | 行が失われている（U2a2では止まらないはず） |

### 手順2：通信が止まらないか

1. 30分以上再生する（できれば1時間）
2. `[DIAG]` の `unplugged` が増えても、`link L3` のままで再生が続くかを見る

### 手順3：Macのスクリプトの停止と再起動

1. `Control`＋`C` でスクリプトを止める。Cardputerは5〜11秒ほどで `LINK L0` 相当（最下行が `WiFi …`、`I` の表示なら `L0`）になる
2. スクリプトをもう一度起動する。**「Linked with the Cardputer」と出て、受信を始める**ことを確かめる
3. ケーブルを抜き差しした場合も、同じく戻るか

### 手順4：Wi-Fi

1. 職場で中継がつながっている間、ターミナルに `[WIFI] paused: the USB relay is in use` と出て、`[WIFI] connecting` が出ないこと
2. スクリプトを止めると、`[WIFI] resumed: no USB relay` と出ること
3. 家（スクリプトなし）では、Stage 3-3と同じくWi-Fiで再生できること

### 手順5：UFO

1. `L` でLocation画面を開く。UFOが地球儀の右上の奥から現れ、右側をゆっくり下りて、右下の奥へ隠れる。6秒ほどして、また上から
2. 国名・都市名・「(now)」が隠れないこと。移動の跡やちらつきがないこと
3. JAPAN〜WORLD（WORLDは地球儀が回り続ける）を切り替えても崩れないこと

## 13. 実機試験の結果（2026-10-21、作者）

| 項目 | 結果 |
| --- | --- |
| USB中継での再生 | 成功 |
| 連続再生 | 約15分 |
| 音切れ | 再生を始めた直後に一時的な音切れがあったが、その後は安定 |
| リンク | L3のまま |
| `isPlugged()` | 一時的にfalseになることがあったが、通信は続いた（U2a2の修正どおり） |
| Macのスクリプトの停止と再起動 | 再起動するとすぐに放送が戻った |
| Location画面 | 表示しても音声の再生は安定していた |

- 第2節の修正（`isPlugged()` を状態に使わない、L0で常にHELLO）は、実機で効果を確かめた
- 第3節の音切れの原因は、まだ決まっていない（再生直後の一時的な音切れは残る）
- UFOの軌道は、地球儀の奥に隠れる時間が長く、演出としての効果が弱かった。U2a3で変更する
