## 1. 変更内容

周波数表示の左側に、1980年代のオーディオ機器風の8段レベルメーターを追加した。それ以外（音声再生、ノイズ生成、AUTO／MANUAL選局、U135の操作、Wi-Fi設定、NVS）は変更していない。該当するコードがStage 2-3と同じであることを、差分で確かめた。

### 表示

| 項目 | 内容 |
| --- | --- |
| 形 | 横長の長方形（幅22×高さ4ピクセル）を縦に8個。各段は1色で塗りつぶし、横には分割しない |
| 隙間 | 各段の間に2ピクセル |
| 色（下から） | 緑4段、黄2段、赤2段 |
| 消灯時 | 同じ形を暗い色（各色の約20%の明るさ）で残す |
| 位置 | x＝6〜27、y＝20〜65（周波数の数字の高さに合わせた）。周波数の数字は「88.7」でx＝56から始まるので重ならない（フォントの文字幅の表から計算） |
| 装飾 | 外枠・丸いLEDはなし |

### 動作

| 項目 | 内容 |
| --- | --- |
| 何を測るか | 放送の音声をデコードしたPCMの実効値（RMS）。スピーカーの音量を掛ける前の値なので、音量のつまみには連動しない（チューナーのメーターと同じ考え方） |
| 測り方 | 音声の出力（`AudioOutputM5Speaker`）がスピーカーに渡すバッファごとに、もともと備えている「モニター」機能で受け取り、2乗の和から実効値を出す（約10ミリ秒ごとに1回の平方根計算）。FFTは使わない |
| 目盛り（RMS、dBFS） | 1段目から順に −36／−30／−25／−21／−17／−14／−11／−8 |
| 反応 | 上がるときはすぐ（1回の更新で）、下がるときは1回の更新で0.25段ずつ（8段から0段まで約1秒） |
| 更新 | 画面は約30回／秒で値を読み、**変わった段だけ**を描き直す |
| 点灯する条件 | 放送の再生中（PLAYING）で、MP3デコーダーが音を出していて、ミュートでなく、ダイヤルがその局の周波数に合っていて、選局の操作中でないとき |
| 消灯する場合 | MANUALの局間ノイズ、接続中、バッファ中、受信失敗、ミュート中、選局中（ダイヤルを回してから0.35秒の間）、局のない周波数 |
| ノイズで点灯しない仕組み | 再生用タスクが、MP3デコーダーが動き始めたときだけ「放送の音」という印を立てる。ノイズに切り替えるときと、ストリームを止めるときに印を下ろす。印がないと、メーターは測定値を受け取らない |
| ピークホールド | なし（今回は不要） |

### 音声への影響を避けるために

- 測定は、音声の出力が既に呼んでいる関数の中で行う。新しいタスク、新しいバッファ、出力への新しい操作はない
- 測定の計算は、1バッファあたり約1,000回の掛け算と1回の平方根
- 描画は画面のタスク（コア1）で行い、変わった段の長方形を塗るだけ（1回の更新で多くても8個）

## 6. 放送局についての調査（実装はしない）

### 6.1 今の登録方式

| 項目 | 内容 |
| --- | --- |
| 場所 | `stations.h` の定数の配列。1局ごとに「局名・国名・URL・仮想周波数」の4つ |
| 検査 | 周波数の重複、範囲外、並び順の誤りは、ビルド時に `static_assert` で止まる |
| 追加の方法 | `stations.h` を書き換えてビルドし直し、Launcherから新しい版を導入する。本体の上で追加・編集する仕組みはまだない |
| 保存 | NVSにもSDカードにも保存しない（プログラムに組み込み） |

### 6.2 登録できる局の数

| 制約 | 内容 |
| --- | --- |
| メモリ | 1局あたり、配列16バイト＋文字列（フラッシュ）。数百局でも問題にならない |
| 周波数の範囲 | 80.0〜90.0 MHzを0.1 MHz刻みで使うと、**最大101局**（MANUALで1局ずつ合わせられる上限） |
| 画面 | 目盛りは0.1 MHzあたり約2ピクセル。局の印（3ピクセル）が重ならないためには、局の間を0.2 MHz以上空ける必要がある。目盛りで見分けられ、MANUALで探す楽しさが残るのは、**20〜30局程度**が目安【推測】 |
| 増やす場合 | 周波数の範囲を広げる（例：76.0〜108.0）。目盛りの数字と間隔の見直しが必要 |
| 処理 | 選局のたびに全局を順に調べるが、数百局でも問題ない時間【推測】 |

**注意：仮想周波数と実在の局の周波数**
今の目盛り（80.0〜90.0 MHz）は、日本のFM放送の周波数帯（76〜95 MHz）の中にある。例えば首都圏では、80.0／81.3／82.5 MHzなどに実在のFM局がある。日本の局を追加するときに、実在の周波数とは違う仮想の数字を割り当てると、混乱を招く可能性がある。追加する前に、周波数の割り当て方の方針（実在の周波数に合わせる／わざと避ける／範囲を変える）を決めたほうがよい。

### 6.3 再生できる音声形式（今のコード）

| 項目 | 対応 | 根拠 |
| --- | --- | --- |
| MP3 | **対応**（今使っている唯一の形式） | `AudioGeneratorMP3`（ESP8266Audio 2.4.1） |
| 通信 | **HTTPだけ**。HTTPSは使えない | ストリームの取得に、暗号化しない `NetworkClient` を使っている（`AudioFileSourceHTTPStream.h`）【確認】 |
| HTTPからHTTPSへの転送（リダイレクト） | 転送には従うが、転送先がHTTPSなら再生できない | `setFollowRedirects(HTTPC_FORCE_FOLLOW_REDIRECTS)`【確認】 |
| URLの形 | 音声そのものを直接配信するURLだけ。再生リスト（`.m3u`、`.pls`）は読まない | ICYストリームの処理に再生リストを読む処理がない【確認】 |
| HLS（`.m3u8`、小分けにした配信） | **非対応** | 同上 |
| AAC | 今のコードでは**非対応**。ライブラリにはAAC（AAC-LC）のデコーダーがあるので、追加はできる | `AudioGeneratorAAC`【確認】。メモリとフラッシュの量は未測定 |
| HE-AAC（AAC+） | ライブラリの設定で、HE-AACの部分（SBR）が無効になっている。高音域が欠ける、または再生できない可能性がある | `HELIX_FEATURE_AUDIO_CODEC_AAC_SBR` が定義されていない【確認】。実際の再生は【未確認】 |
| 曲名（ICYメタデータ） | 対応（Stage 2-3以降はシリアルに出力） | ― |
| ビットレート | 128 kbpsのMP3で再生を確認（Stage 2-1〜2-3）。それ以外は未確認 | ― |

HTTPSに対応するには、暗号化（TLS）の処理に数十KBのメモリが必要で、PSRAMのない本機では再生と両立するか未確認（設計書 3.7節）。

### 6.5 調査中に見つかったこと：ESP8266Audioのライセンス

- 音声の再生に使っている **ESP8266Audio は、GNU GPL v3 のライセンス**（`LICENSE` ファイルと各ソースの先頭で確認）
- RADIO DAYSの自分のコードはMITのままでよい（MITはGPLと組み合わせられる）。ただし、ESP8266Audioを含めた **`.ino.bin` を配布する場合は、GPL v3の条件（対応するソースコードを入手できるようにする、など）に従う必要がある** と考えられる
- 公開や配布の前に、どう扱うかを決める必要がある（法的な判断ではない。必要に応じて確かめる）
