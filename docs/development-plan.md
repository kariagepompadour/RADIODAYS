# RADIO DAYS 開発計画

- 版：第2版（2026-10-20）。1.2MBを超えるアプリとする方針、Stage 2-1に進む条件、NVSの検証手順（D0〜D3）、SDカードを使わない方針を反映した
- 設計書：[design.md](design.md)

## 共通のルール

- 各段階は**新しいフォルダ**で作る（例：`firmware/RadioDays_2_1/`）。前の段階の成功版は変更しない。導入したバイナリのSHA-256を記録する
- **本体への書き込みは、Launcherからapp-onlyの `.ino.bin` を導入する方法だけ**で行う。Arduino IDEの「書き込み」とmerged imageは使わない
- **導入するのは、試験したものと同じバイナリだけ。** ビルド設定（design.md 3.5.2節）を固定し、ビルドのたびにSHA-256を記録する
- **導入の前に、PManで空き（FREE）がアプリの大きさ以上あることを確かめる。** 導入中に「Need …」の画面が出たら、必ず「Cancel」を選ぶ（design.md 3.5.1節）
- 本体への書き込み（導入）は、**その都度、作者の了承を得てから**行う
- Media Jog、SOUND TERRARIUM、Launcherのソースとバイナリは変更しない。パーティションの作成・削除・変更、NVSの消去・初期化は行わない
- SDカードは使わない（design.md 3.8節）
- 実機で試す前に、何を書き込むのかと、元に戻す方法（Launcherへの戻り方、ダウンロードモード）を確認する

## Stage 2：基本動作

### Stage 2-0：容量の試作（完了。ビルドのみ）

- 結果：構成B（Hardware CDC and JTAG）で1,299,328 B。標準の1.2MBでは残り11,392 Bで、目安の64KBに届かなかった。詳細は [stage-2-0-size.md](stage-2-0-size.md)

### Stage 2-1：実機での基本動作

**状態（2026-10-20）**：ビルドと静的確認まで完了。実機での確認はこれから。結果と手順は [stage-2-1.md](stage-2-1.md)。進む条件のうち、空き容量は作者がPManで約4MBを確保して解消した。NVSの読み出し（D0〜D3）は、作者の判断で今回は行わない。

**作るもの**（`firmware/RadioDays_2_1/`）

- 起動直後は**待機画面**で止まる。この間、RADIO DAYS自身のコードはNVSに書かず、Wi-Fiも始めない。キーを押すと先に進む（NVSの検証のD1のため）。D1は「導入から待機画面までの変化の合計」で、Launcherの処理とRADIO DAYSの初回起動時の処理（Arduinoコア・ライブラリの初期化）を含む（design.md 3.6.2節）
- NVSへの書き込みは1つの関数だけを通し、名前空間・キー・理由をシリアルに記録して回数を数える
- `nvs_get_stats()` の結果（使用中・空きのエントリ数）を画面とシリアルに出す
- Wi-Fi（`WiFi.persistent(false)`。設定はGitに入れない `secrets.h`）、1局のMP3再生、音量、ミュート
- 空きヒープと、最大の連続空き領域の記録

**確認すること**

| 確認すること | 判定・記録 |
| --- | --- |
| 導入できる（1.2MBを超える大きさで） | 「Need …」の画面が出ずに導入できること。導入後のPManで、RADIO DAYSの領域の位置と大きさを記録し、他の領域が変わっていないこと |
| Launcherから起動し、Launcherに戻れる | 起動できること。戻り方を記録する |
| Flash Size 8MBの設定で動く | 起動できること（design.md 3.5.2節の未確認事項） |
| Wi-Fi接続 | 接続できること。切断から再接続できること |
| 1局のMP3を再生（スピーカー、イヤホン） | 10分以上、途切れずに再生できること（仮） |
| 音量・ミュート（U135） | 押しながら回す操作の使いやすさを、実際に触って判断する |
| 空きヒープと、最大の連続空き領域 | 再生中の最小値を記録する |
| NVS | design.md 3.6.2節の手順（D0〜D3）と合格条件 |
| ほかのアプリへの影響（回帰） | LauncherからMedia JogとSOUND TERRARIUMを起動し、保存してある設定が残っていること。Media JogのBLEは、再ペアリングが必要になった場合は記録する（Launcherの入れ替えの仕組みによるもの。design.md 3.5.3節） |

## Stage 3：ラジオの画面

- アナログ式の選局目盛り、指針、局名・国名、接続状態、音量の表示
- プリセット一覧から複数の局を選ぶ。つながらない局は飛ばし、一定回数失敗したら止めて表示する
- キーボードでのWi-Fi設定（接続に成功してから保存する）
- 音量の保存（最後の変更から数秒後にまとめて書く）
- 判定：選局の操作で画面が引っかからないこと。再生中の空きヒープがStage 2-1から大きく減っていないこと。アプリの大きさが、実機の空きの範囲に収まっていること
