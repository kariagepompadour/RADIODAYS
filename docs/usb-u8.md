# U8：AUTOでスケールが次の局まで流れる

- 作成日：2026-10-22
- 状態：**実装、ビルド、ホスト試験まで。実機ではまだ試していない**
- 設計：[auto-glide-proposal.md](auto-glide-proposal.md)（作者の決定：秒速100ピクセル、到着したらすぐ受信、移動中は TUNING... と局名なし、1クリック＝1局）
- もとにした版：U7（変更なし）。中継は `RadioDaysRelay_U4.command`

## 動き
| 操作 | U8 |
| --- | --- |
| AUTOで1クリック | 次（前）の局へ、**20ミリ秒ごとに1段（2ピクセル）＝秒速100ピクセル**で流れる（`GLIDE_STEP_MS`）。動き始めに今の局を止めて雑音（MANUALと同じ処理）。着いたら**すぐ**その局を受信（350ミリ秒待たない）。途中の局は受信しない |
| 同じ向きに続けて回す | 1クリック＝1局を足す。最後の局を越えて次の周へも進む。**まだ着いていない局は最大3局**（`GLIDE_MAX_STATIONS`）。それを超えるクリックは捨てる（ためない）。局を通り過ぎるたびに1局分の空きができる |
| 逆向きに回す | その時の表示の位置から向きを変え、逆向きで最も近い局へ（ふつうは出てきたばかりの局）。先の局の予定は捨てる。2クリック以上なら、そこからさらに局を足す |
| 継ぎ目 | 最後の局→最初の局も、その逆も、1段ずつ途切れずに流れる |
| 表示 | 動いている間：状態「TUNING...」、局名の行は空。着いたら局名と受信の状態 |
| A（モード切替） | その場で止まり、MANUALに（局の間なら雑音のまま） |
| Locationの切り替え | 動きは終わり、新しいLocationの最初の局 |
| MANUAL | U7と同じ（`tuneBy()` のMANUALの部分はU7と1文字も違わない） |

**上限を3局にした理由**：1局はおよそ0.36〜0.46秒なので、3局で最大約1.4秒。ノブをすばやく回すと数クリックが一度に来るが、手を止めてから1.4秒以内に止まる。3局のLocationなら一周（同じ局に戻る）まで回せる。上限を超えたクリックを「後で動く」ためにためると、手を止めても長く動き続けるので、捨てる方式にした。局を通り過ぎるたびに空きができるので、1局分より遅いペースで回している限り、クリックは捨てられない（試験で確認）。

## 描画と音声
- 動いている間は、`loop()` の中で時刻から位置を進め、**ダイヤルだけ**を20ミリ秒ごとに描く（U6の「変わった列だけ」の描き方。1段の描き直しは約1.5ミリ秒【推定】）。`loop()` が遅れても速さは同じ（1回に最大4段まで進め、それ以上遅れたら今から数え直す）
- 動いている間は局の音声を受けていない（雑音だけ）ので、描画が増えても受信のバッファーには影響しない
- 新しいタスク、待ち、画面外のキャンバスはない
- 音声の処理（`decodeTask`・`stopStream`・`produceNoise`）、USBのリンク、中継はU7と同じ。「局→雑音→局」はMANUALで局をまたぐときと同じ流れ（USBでは中継へ `STOP` のあと `TUNE`。U2a2以降のシミュレーションで確かめている流れ）

## 実機で確かめること
1. AUTOで1クリック：目盛りがなめらかに流れ、局の印が指針で止まる。動いている間の雑音、着いてからの受信（Wi-FiとUSB中継の両方）
2. 速さ（秒速100ピクセル）が見やすいか。`GLIDE_STEP_MS` で調整できる
3. すばやく何クリックも回したとき、逆に回したとき、継ぎ目
4. 動いている間の表示（TUNING...、局名なし）
5. 雑音から受信に移るときの音、USB中継のターミナルの表示（Stopped → Tuning）
6. MANUAL、時計、ダイヤルの見た目はU7と同じ
