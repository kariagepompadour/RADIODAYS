# Stage 2-0：容量の試作（ビルドのみ）

- 実施日：2026-10-20
- **本体への書き込みは行っていない。** スケッチは一度も実機で動かしていない
- スケッチ：`firmware/RadioDays_2_0/`（公開リポジトリには含めていない）（容量の測定用。導入しないこと）

## 1. 目的

RADIO DAYSに必要な部品をすべてリンクした状態で、標準のアプリ領域（1,310,720 B）に収まるかを確かめる。

スケッチに含めたもの（どれも実際に呼び出しているので、リンクから外れない）：

- Wi-Fi（ステーション）、ICYストリーム、ストリーム用バッファ、MP3デコーダー（ESP8266Audio）
- M5Unifiedの `Speaker`（ES8311）
- M5Cardputerのキーボードと画面（内蔵フォントのみ）
- U135（Grove I²C、`Wire`）
- Preferences（名前空間 `radiodays`）

含めていないもの：ラジオの画面（目盛り・指針）、Wi-Fi設定画面、局の一覧の管理、NVS点検の機能。**これらの分だけ、実際のアプリはさらに大きくなる。**

## 2. ビルド環境

| 項目 | 値 |
| --- | --- |
| ボードパッケージ | m5stack:esp32 3.3.9（ボード：M5Cardputer） |
| ライブラリ | M5Unified 0.2.25、M5Cardputer 1.1.1、M5GFX（インストール済みの版）、M5Unit-Encoder 0.0.2、ESP8266Audio 2.4.1 |
| ツール | Arduino IDE同梱のarduino-cli |
| その他の設定 | CDC On Boot：Enabled。それ以外はボードの既定値 |

## 3. 結果

| 構成 | USB Mode | 標準の設定（1.2MB APP）でのビルド | アプリの大きさ | 1,310,720 Bとの差 | 静的RAM（data＋bss） |
| --- | --- | --- | --- | --- | --- |
| A | USB-OTG（TinyUSB） | **不可**（text section exceeds available space） | 1,352,752 B（Huge APP設定で測定） | **42,032 B超過** | 92,772 B |
| B | Hardware CDC and JTAG | 可 | 1,299,328 B | **残り11,392 B** | 60,700 B |

SHA-256（記録用。どちらも導入しない）：

- A（Huge APP設定）：`e6b90338bcbaf2fe1bcdb8fbe308bbb01518913497b5147279a26e79e3f67e8d`
- B（標準の設定）：`ad49d542d2ff6f905fd056839133849331065964eac10b81b62170d718eccae6`

参考：同じ構成BをHuge APP設定でビルドすると1,299,360 B（32 B多い）。パーティション設定だけを変えても、バイナリは完全には同じにならない。

## 4. 構成Bの内訳（リンカーのmapファイルから集計）

| 部分 | 大きさ |
| --- | --- |
| Wi-Fi・TCP/IP（libnet80211、liblwip、libpp、libwpa_supplicant、libphy） | 約44.1万B |
| ESP8266Audio | 約11.8万B（うちMP3デコーダーのlibmad `layer3.c` 5.3万B、`huffman.c` 3.6万B） |
| M5GFX | 約10.5万B（うち内蔵フォントの表 `lgfx_fonts.cpp` 1.7万B） |
| libmbedcrypto | 約6.8万B（Wi-FiのWPAでも使う） |
| M5Unified | 約5.7万B |
| HTTPClient＋Network | 約2.8万B |

集計は、mapファイルのフラッシュ領域とIRAM領域の配置を、ライブラリごとに合計したもの。合計はアプリの大きさと完全には一致しない。

## 5. 判定

- 目安（今後の画面の追加分として64KB以上の余裕）に対して、**構成Bでも11,392 Bしか余裕がない。不合格。**
- 削れる候補と見込み（どれも未確認）：

| 候補 | 見込み |
| --- | --- |
| HTTPClientを使わず、`WiFiClient` で自前のICY読み取りを書く | 最大で2〜3万B【推測】 |
| フォントや描画の機能を絞る | 数千〜1万B台【推測】 |
| MP3デコーダーを、より小さいもの（Helixなど）に替える | 不明。作業量が大きい【未確認】 |

- 削れたとしても、ラジオの画面・Wi-Fi設定画面・局の管理を載せる余裕は少ない【推測】

## 6. 次に決めること

1. **Launcherの実機確認（読むだけ）**：Launcherの版と、PManのパーティション表・空き容量を見る（design.md 3.5節）
2. その結果で、次のどちらにするかを決める
   - **1.2MBに収める**：構成B＋上の削減。画面をごく簡素にする
   - **1.2MBを超えるアプリにする**：Launcherが、イメージの大きさに合わせてアプリ領域を作る方式であることを実機で確かめる。そのうえで、了承を得てから導入を試す

## 7. その後の決定（2026-10-20）

1.2MBに収めるための過度な機能削減はしない。Launcher 2.9.1で安全に扱えるなら、1.2MBを超えるアプリとする。経緯はdesign.md 3.1節・3.5節、CHANGELOG.mdに記録した。
