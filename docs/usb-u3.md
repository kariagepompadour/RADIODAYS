# U3：USB中継だけのときも、時計・太陽・月を出す

- 作成日：2026-10-21
- 状態：**実装、ビルド、ホスト試験、シミュレーションまで。実機ではまだ試していない**
- 設計：[usb-u3-time-design.md](usb-u3-time-design.md)（作者の承認済み。時刻のもとを示す「M」などの表示は付けない）
- もとにした版：U2a4（変更せず保存）。Macの中継U2a2も変更せず保存
- Stage 3-3以前、U1、U2a、U2a2、U2a3、U2a4のファイルは変更していない（SHA-256の一致を確認）

## 1. 変更の内容

| 項目 | U2a4 | U3 |
| --- | --- | --- |
| 時刻のもと | SNTP（Wi-Fi）だけ | SNTP、または**Macの中継**（SNTPが同期していないとき） |
| USBだけのとき | 時計は `--:--`、空の窓は空 | 中継が見つかると、時計・太陽または月が出る |
| 時計の表示 | 日本時間（JST） | 同じ。時間帯の設定を、SNTPのときだけでなく**起動時に1回**行う |
| 太陽・月 | UTCとLocationの緯度経度 | 同じ（描画の処理は変えていない） |
| 画面のデザイン | ― | 変えていない |

### 1.1 やり取り（追加分だけ）

| 方向 | 行 | いつ |
| --- | --- | --- |
| Cardputer→Mac | `@RD TIME <id>` | 中継が見つかったとき。書けなかったとき、または10秒たっても返事がないときは、次の選局（TUNE）の直前か、待機中に、もう一度（新しいidで）。1回のつながりにつき最大5回 |
| Mac→Cardputer | `\nRDTIME <id> <UTCの秒>\n` | `@RD TIME` を受け取ったとき。**ただし、局のデータ（MP3）を送り始めた後（`RDSYNC` の後）は答えない** |

- Macが送るのは**UTCの秒だけ**（Perlの `time`。Macの時間帯の設定に関係しない）。日付や時刻の文字、Macのローカル時刻、時間帯は送らない
- Cardputerは、2025年より前・2100年より後の値、数字でない値、idの違う返事を使わない
- SNTPで同期した後は、Macの時刻を使わない。Macの時刻を使った後でSNTPが同期すれば、SNTPが上書きする（どちらもUTC）
- 一度合わせると、USBが抜けても本体のタイマーで時計は進む。再起動すると消え、中継がつながると再び受け取る

### 1.2 時刻を頼んですぐにL3へ進んでも、時刻を失わず、音声に文字が混ざらない理由

| 場面 | 動き |
| --- | --- |
| 中継が見つかり、すぐに選局する | Cardputerは `@RD TIME` を `TUNE` より**前に**書く。Macは届いた順に処理するので、`RDTIME` を `RDSYNC` より**前に**書く。Cardputerは `RDSYNC` を待っている間（L2）も `RDTIME` を受け取る。そのため、L3に入る前に時刻は届いている |
| `@RD TIME` が書けなかった（HWCDCが忙しい） | 次の `TUNE` の直前に、新しいidで頼み直す（その返事も `RDSYNC` より前に来る） |
| 返事がない（中継U2a2、またはMacが局のデータを送っていた） | 10秒ごと（待機中）か次の選局の前に、最大5回まで頼み直す。L3の間は頼まない（次の機会を待つ） |
| 音声に文字が混ざらない | Cardputerは、L3の間は `@RD TIME` を書かない。Macは、`RDSYNC` の後は `@RD TIME` に答えない。返事の行は、Cardputerが局のデータを受け取る前にしか届かない |

## 4. 試験

### 4.1 時刻のホスト試験（新規：`tools/time-test/`）

```bash
sh tools/time-test/run_time_test.sh
```

**リンクの時刻の処理（`link_time_test`）：15項目すべて合格**

| 確かめたこと |
| --- |
| 中継が見つかると `@RD TIME` を1回書く |
| idの違う返事、2025年より前、2100年より後、数字でない、長すぎる、空の値は使わない |
| 2回に分かれて届いた返事を受け取り、受け取ってからの時間もわかる。1回だけ渡す |
| 返事を受け取った後は、そのつながりの間はもう頼まない |
| 中継U2a2のように答えない場合：最大5回まで。リンクは保たれる |
| **`TIME` は `TUNE` より前に書かれる（`TUNE` の直前に重ねて頼まない）** |
| **返事が `RDSYNC` の直前に届いても受け取り、そのまま受信（L3）に進む** |
| **L3では、時刻の行はMP3のデータとしてデコーダーに渡るだけで、時刻としては使わない。L3の間は `TIME` を書かない** |
| `TIME` が書けなかった場合：`TUNE` の直前に新しいidで頼み直す。古いidへの返事は使わず、新しいidへの返事をL2で受け取る |

**スケッチの時計の処理（`clock_test`。スケッチの関数を切り出して実行）：11項目すべて合格**

| 確かめたこと |
| --- |
| `clockInit()` の後は、PCの時間帯がニューヨークでもロンドンでも、UTC 00:00が日本時間09:00と表示される |
| Macの時刻：2025年より前・2100年より後は使わない。正しい値は、受け取ってからの時間を足して設定する。SNTPで同期した後は使わない |
| 昼と夜（UTCと緯度経度だけ）：東京（02:00は夜、10:00は昼）、ロンドン（18:00・02:00は夜）、ニューヨーク（13:00は昼、21:00は夜）。PCの時間帯を変えても同じ |
| 月の満ち欠け：2024年1月の新月と満月 |

### 4.2 シミュレーション（`tools/usb-relay/sim3/`。sim2にU3の時刻の試験を加えたもの）

```bash
sh tools/usb-relay/sim3/run_sim.sh             # U3＋中継U3：sim2の全項目と時刻
sh tools/usb-relay/sim3/run_sim.sh --negative  # 確認用
sh tools/usb-relay/sim3/run_sim.sh --oldrelay  # U3＋中継U2a2
```

| 実行 | 結果 |
| --- | --- |
| U3＋中継U3 | **45項目すべて合格**（sim2の41項目＋時刻の4項目） |
| 確認用（`--negative`） | あふれを検出（テストが正しく働く） |
| U3＋**中継U2a2** | **8項目すべて合格**：時刻は届かない（U2a4と同じ）、`TIME` は12秒で2行（最大5行）、再生・選局は今までどおり |

**時刻の項目（U3＋中継U3）**

| 項目 | 結果 |
| --- | --- |
| 中継が見つかると時刻が届く | 合格。Macの時計との差0秒 |
| **時刻を頼んだ直後に選局し、すぐL3に入る**（Macのスクリプトを止めて起動し直し、中継が見つかった瞬間にTUNE） | 合格：**時刻は届き、新しい局のデータに他のバイトが1つも混ざらない**（10,677行をすべて確認） |
| リンクがつながったときの `TIME` の行が書けない | 合格：TUNEの前に頼み直し、時刻が届く |
| 局のデータを送っている最中に `@RD TIME` が届く（プロトコルにはない操作） | 合格：Macは答えない。データに文字は混ざらない |
| 全体 | あふれ0、読むのは常に1つ、**L3の間に `TIME` を書いた回数0** |

**試験で見つかった不具合（修正済み）**

1. **Macの中継が、時刻を小数で送っていた**（`time` が、スクリプトが読み込んでいる `Time::HiRes` のもので、小数を返す）。Cardputerは数字以外を受け付けないので、時刻が届かなかった。整数の秒（`int(time)`）に直した。Cardputerの検査が正しく働いた例
2. **リンク：中継が見つかった直後の選局で、`TIME` を2回頼んでいた**（最初の返事を捨てていた）。直前の依頼が書けた場合、10秒以内なら頼み直さないように直した
3. 試験の誤り2つ（ホスト試験の基準の時刻の計算、シミュレーションで古い局を読むときの検査の取り違え）。直してから、すべての試験をやり直した

## 5. 実機で確かめる手順（導入は作者の判断で）

### 準備

1. PManで、空き（FREE）が0x150000以上あることを確かめる
2. Launcherで `firmware/RadioDays_U3/RadioDays_U3.ino.bin` を入れる（「Need …」が出たら「Cancel」）。START画面の右上が「U3」
3. Macでは、**新しい `tools/usb-relay/RadioDaysRelay_U3.command`** を使う（U2a2の中継でも再生はできるが、時刻は届かない）

### 手順

| # | 場面 | 期待すること |
| --- | --- | --- |
| 1 | 職場：`U`（または普通に）で起動し、中継U3を起動 | 中継が見つかると、ラジオの画面の時計に日付と日本時間が出て、空の窓に太陽か月が出る。ターミナルに「Sent the time to the Cardputer (UTC).」 |
| 2 | Locationを切り替える（JAPAN、USA、UK、FRANCE） | 空の窓の昼と夜が、その都市の太陽の高さで変わる（例：日本の昼は、ロンドンでは夜） |
| 3 | USBを抜く | 時計は進み続ける（太陽・月も出たまま）。つなぎ直すと、また時刻を受け取る |
| 4 | 中継U2a2で起動する | U2a4と同じ（時計は `--:--`）。再生に影響しない |
| 5 | 家（Wi-Fi） | U2a4と同じくSNTPで時計が出る |
| 6 | 再生、選局、音量、UFO、`U` キー | U2a4と同じ。15分以上の再生で、音に余計な音（文字が混ざった音）がない |
| 7 | 時計の正確さ | 数時間後に、Macの時計と比べる（ずれは数秒以内の見込み【推測】） |
