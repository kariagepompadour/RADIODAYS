## 3. 設計からの細かな変更と、実装でわかったこと

| 項目 | 内容 |
| --- | --- |
| **シミュレーションで見つけた不具合（修正済み）** | 「5秒データなし」の判定で、再生用タスクが受信時刻を書いた直後に、リンクの管理が古い「今」の時刻と比べると、引き算が負になり、とても大きな値になる。そのため、データが届いているのにSTOPを送っていた。符号つきの比較に直した。実機でも起きたはずの不具合 |
| MOREの出し方 | 設計どおり2KB単位。ただし、空きがあるときは、まとめて1行で出す（例：最初は `MORE <id> 14336`）。行の数を減らすため |
| USBが抜けたことの判定 | 設計では `Serial.isConnected()`。Arduinoコアを読むと、これは「Macが最近データを受け取ったか」で、Macのスクリプトが動く前はfalseのまま。そのため、USBの信号の有無（`Serial.isPlugged()`）を使い、**1秒続けてないとき**に抜けたとみなす（数ミリ秒のぶれがあると、コアのコメントにある） |
| 送信バッファー | 256 Bから1,024 Bにした。要求と記録の行が重なっても、途中で切れにくくするため |
| USBで受信した局の曲名 | 表示されない（Macは曲名の情報を求めないため。曲名は、もともとシリアルの記録だけに出していた） |
| 中継が使えなくなった後 | 再生用タスクは止まり、次に局を開くとき、その時点で使える方（中継、またはWi-Fi）を使う。**再生中の自動切り替え（U2b）ではない**。この動きは試していない |
| 画面 | 最下行のWi-Fiの欄が、中継が見つかると `USB relay …K` になる。つながらないときの表示は `WAITING FOR WI-FI/USB` |

## 5. シミュレーション（2026-10-21）

```bash
sh tools/usb-relay/sim/run_sim.sh
```

| 項目 | 内容 |
| --- | --- |
| しくみ | Cardputer側は、ファームウェアと同じ `radiodays_link.h`。偽のUSB割り込みは、受信キュー（16KB）に入らないバイトを捨てる（Arduinoのドライバーと同じ）。割り込み・リンクの管理・再生用タスクを、3つのスレッドで動かす |
| Mac側 | 実際の `RadioDaysRelay_U2.command` を、仮想シリアルポート（pty）につなぐ。許可するのは `localhost:18761` だけ |
| 放送局の代わり | `station_server.py`（このMacの中だけ）。局ごとに、`A:000000`、`A:000001`…という行を送る。受け取った側は、すべてのバイトがどの局のものか、抜けがないかを確かめる |

**結果：37項目すべて合格**（2回目の実行。1回目は、上の不具合と、試験の判定の誤り1件で不合格。両方を直して、全項目をもう一度実行した）。

| 分類 | 合格した項目 |
| --- | --- |
| 正常系 | 中継の発見／1局を16KB/秒で8秒（最初に64KBを一気に送る局）／10回の選局／読み出しを4秒止める（キュー最大14,768 B、タイムアウトなし）／4倍の速さ（62.4KB/秒）／同じホストへの302（相対・絶対）／`ICY 200 OK` |
| 混入と境界 | 古い局がキューとクレジットを満たしている最中の選局／返事の前に5回TUNE（最後の局だけ）／STOP→TUNE、TUNE→STOP→TUNE／古いidのMORE・切れたMOREを無視／**返事を1バイトずつに分けて受信**／**古い局のデータに、偽のRDSYNC・RDNAK・RDHOST（古い局自身のidを含む）**／読み出し中にリンクがL3を出る（同時に読むのは常に1つ） |
| 切断とタイムアウト | 局が応答しない（10.0秒で `RDNAK CONN`）／局が送信中に切れる（Macがつなぎ直し、本文だけが続く）／選局中（L2）にUSBが抜ける／Macのスクリプトを止める（L3→L1→TUNEに返事なし→L0）／スクリプトをもう一度起動（新しいidでつながる） |
| 許可ホストとポート | ポート・ホスト・別ポートへのリダイレクト・別ホストへのリダイレクト・HTTPSへのリダイレクト・リダイレクトの繰り返し・404・不正なURL7種類が、正しい理由で拒否。**拒否したポートへの接続は0回** |
| 全体 | 受信キューのあふれ0バイト（約17MBを受信、約168KBを捨てた）、同時に読んだのは常に1つ |
| 確認用（`run_sim.sh --negative`） | キューを超えるクレジットをわざと出すと、897,952バイトのあふれを検出した。**テストが、あふれを正しく見つけられる** |

**シミュレーションでわかるのは、やり取りの正しさだけ。** 次のことは、シミュレーションではわからない。

- 実機での音
- 実機のUSBの速さ
- MP3デコーダーとの組み合わせ
- 画面の見た目
- Macでポートが消えたときの動き（シミュレーションでは「抜けた」をCardputer側だけで模擬した）
- 本物の放送局での動き（シミュレーションはネットワークを使わない）

## 6. 実機で試す手順

### 準備

1. **Cardputerに `firmware/RadioDays_U2a/RadioDays_U2a.ino.bin` を入れる。** いつもどおりLauncherから入れる（「Need …」が出たら「Cancel」）
2. **職場のMacに `tools/usb-relay/RadioDaysRelay_U2.command` をコピーする。** U1と同じフォルダでよい
3. （任意）Macで、全局が許可されているかを確かめる。ターミナルで `perl ` と入力し、スクリプトをドラッグしてから、続けて ` --check-url http://stream.radioparadise.com/mp3-128` と入力してReturn。`OK` と出ればよい

### 手順1：中継が見つかるか

1. CardputerをUSBデータケーブルでMacにつなぎ、LauncherからRADIO DAYS U2aを起動する。起動画面の右上が「U2a」になっている
2. キーかノブを押してラジオの画面に進む
3. Macで、ターミナルに `perl ` と入力し、`RadioDaysRelay_U2.command` をドラッグしてReturn（U1と同じ）
4. ターミナルに「Port … opened」→「Linked with the Cardputer.」と出る
5. **Cardputerの最下行が `USB relay …K` になり、局を受信して音が出る**（「CONNECTING」→「BUFFERING」→「PLAYING」）

### 手順2：選局

| 確かめること | 期待すること |
| --- | --- |
| AUTOで、ノブを1つずつ回す | 局が変わり、前の局の音が混ざらない。ターミナルに「Tuning …」「Sending …」 |
| AUTOで、ノブを速く何回も回す | 止めた局だけが鳴る（途中の局は開かない） |
| `A` でMANUALにし、局と局の間に回す | 雑音になる。ターミナルに「Stopped.」。局の周波数に戻すと、また受信する |
| `L` でLocationを変える（JAPAN、USA、UK、FRANCE、WORLD） | それぞれの局がUSBで鳴る |
| 音量・ミュート | 3-3と同じ |

### 手順3：Location画面のUFO

| 確かめること | 期待すること |
| --- | --- |
| `L` でLocation画面を開く | **UFOが右上**（見出しの線のすぐ下）で、ゆっくり浮く |
| ノブで、すべてのLocationを選ぶ | 国名・都市名・「(now)」・局名と重ならない。今のLocationでは、都市名の後ろに「(now)」が出る |
| ノブを速く回す | UFOが消えたり、ちらついたりしない |

### 手順4：10分間の連続再生

10分以上再生して、音の途切れや雑音がないかを聴く。ターミナルの `Sent … KB/s` が約16（128kbpsの局）であることを確かめる。

### 手順5：止めたとき・抜いたとき

| 確かめること | 期待すること |
| --- | --- |
| ターミナルで `Control`＋`C` を押す | 5〜12秒ほどで、Cardputerの表示が「NO SIGNAL」か「WAITING FOR WI-FI/USB」になる。最下行は `WiFi …` に戻る。フリーズしない |
| スクリプトをもう一度起動する | また `USB relay` になり、受信を始める |
| 再生中にUSBケーブルを抜く | 1秒ほどで再生が止まる。フリーズしない（バッテリーで動いている場合）。ターミナルに「Searching again...」 |
| もう一度つなぐ | スクリプトを起動し直さなくても、またつながって受信する |

### 手順6：Wi-Fiだけの場所（家など）

Macのスクリプトを動かさずに使う。**Stage 3-3と同じく、Wi-Fiで再生できる**ことを確かめる（最下行は `WiFi …dBm`）。
