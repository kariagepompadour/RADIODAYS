## 1. しくみ

```text
Radio Paradise ──(有線LAN)── Mac：curl で受信
                               │  Cardputerが「あと2KB受け取れる」と言った分だけ送る
                               ▼
                      USBケーブル（シリアル）
                               ▼
     Cardputer：受信キュー（16KB）→ ストリーム用バッファー（32KB）→ MP3デコーダー → スピーカー
```

### 調査でわかった重要なこと【確認：Arduinoコア3.3.9の `HWCDC.cpp`】

CardputerのUSBシリアル（Hardware CDC）は、受信キューがいっぱいになると、**届いたデータを捨てる**。割り込みの中でUSBの受信バッファーを必ず読み出し、キューに入らなかった分は捨てる作りのため、USBの「相手を待たせる」仕組みは働かない。

さらに、放送局は接続直後にデータをまとめて送ってくる（U0では、10秒で再生に必要な量の約2倍を受信した）。Macから届いた分をそのまま送ると、MP3が欠けて音が乱れる。

**そこで「クレジット方式」にした。**

- Cardputerは、受信キューに空きがあるときだけ、`@RD MORE 2048`（あと2048バイト受け取れる）と送る
- Macは、言われた分しか送らない
- Cardputerは「許可したが、まだ届いていない量」も数えて、キューに入りきる範囲でしか許可しない。このため、データが捨てられることはない

### やり取り

| 方向 | 内容 |
| --- | --- |
| Cardputer → Mac | `@RD HELLO U1`（つながるまで1秒ごと）、`@RD MORE 2048`（クレジット）、その他は記録の行（Macの画面に表示するだけ） |
| Mac → Cardputer | 最初に `RDSYNC` の1行、その後はMP3のデータ（許可された分だけ） |

### 途切れとデッドロックを防ぐ工夫

| 工夫 | 内容 |
| --- | --- |
| 受信と再生の分離 | USBの受信は割り込みでキューに入る。再生用タスクは、キューから32KBのバッファーへ移し、MP3デコーダーに渡す。描画やキー操作は別のタスク |
| 最初の貯め込み | バッファーが3/4（約1.5秒分）たまってから再生を始める。足りなくなりかけたら、また貯めてから再生する（その回数を「underruns」として表示する） |
| デッドロックの回避 | 再生が止まってキューがいっぱいになると、クレジットを出さなくなり、Macは待つ。再生が再開すればクレジットが出る。クレジットを出したのに5秒間データが来なければ、「つながっていない」として待機に戻る |
| バイナリの保護 | Macのスクリプトが、ポートをraw（改行などを書き換えない、8ビット）にする |
| 読み込みの待ち時間 | MP3デコーダーは、データが0バイトだと「終わり」と判断する。そのため、デコーダーからの読み込みは最大0.5秒だけデータを待つ |

## 2. Mac上で行ったテスト（実機の代わり）

実際のMac用スクリプトを、仮想のシリアルポート（pty）につないでテストした。

- ポートの向こう側には、スケッチから取り出したクレジットの処理と、偽のUSB割り込みを置いた。偽のUSB割り込みは、Arduinoのドライバーと同じく、キューがいっぱいならデータを捨てる
- 放送局の代わりに、ローカルのHTTPサーバーから3MBのデータを全速で送った

| テスト | 結果 |
| --- | --- |
| 128kbps（16KB/秒）で25秒再生 | **捨てられたバイト0**、受信データは元のデータと完全に一致、キューの最大は15,360バイト（上限16,384）、16.0KB/秒 |
| 再生が4秒止まる | 捨てられたバイト0。Macは待って、再生の再開後に送信を再開した |
| 64KB/秒で読む（4倍の余裕の確認） | 捨てられたバイト0、64.0KB/秒 |
| （確認用）クレジットなしで一気に送る | **698,094バイトが捨てられ、不合格**。テストが、あふれを正しく見つけられることを確認 |

**このテストでわかるのは、やり取りの正しさだけ。** 実機での音、USBの実際の速さ、ポートを開いたときのリセットは、実機で確かめる必要がある。

## 4. 実機で試す手順

### 準備

1. **Cardputerに `RadioDays_U1.ino.bin` を入れる。** いつもどおりLauncherから導入する
   - LauncherのWi-Fiアップロードは、Wi-Fiのある場所で行う
   - 職場で入れる場合は、SDカードからの導入を使う
   - 「Need …」が出たら「Cancel」
2. **Mac用のファイル2つを、職場のMacにコピーする**（例：デスクトップの「RADIODAYS」フォルダ）
   - `RadioDaysPortCheck_U1.command`
   - `RadioDaysRelay_U1.command`
3. **MacにPerlがあるか確かめる。** 「アプリケーション → ユーティリティ → ターミナル」を開き、次を入力してReturnを押す

   ```bash
   perl -v
   ```

   「This is perl 5」で始まる文章が出ればよい

### 手順1：ポートを開いてもリセットされないか（最初に必ず）

1. CardputerをUSBデータケーブルでMacにつなぎ、LauncherからRADIO DAYS U1を起動する
2. Cardputerの画面に「RADIO DAYS U1」「boot #…」「LINK: waiting for the Mac relay」が出る。**「boot #」の数字を覚えておく**
3. ターミナルに `perl `（perlと半角スペース）と入力し、`RadioDaysPortCheck_U1.command` をターミナルの窓にドラッグして、Returnを押す
   - Finderでファイルをダブルクリックしてもよい。初回は「開発元を確認できない」と出ることがあるので、その場合はファイルを右クリック→「開く」を選ぶ
4. 「Press Return to open …」と出たらReturnを押す。20秒間、Cardputerから届いた行（`@RD HELLO U1` など）が表示される
5. **Cardputerの画面を確認する**

| 画面 | 意味 |
| --- | --- |
| 「boot #」が同じで、「up …s」が数え続けている | **ポートを開いてもリセットされない（よい）。手順2へ** |
| 「boot #」が増えた、またはLauncherの画面になった | ポートを開くとリセットされる。ここで止めて、結果を知らせてほしい |

### 手順2：中継して再生する

1. Cardputerで音量を下げておく（`.` キー。最初は小さい音量で始まる）
2. ターミナルで `perl ` と入力し、`RadioDaysRelay_U1.command` をドラッグしてReturn（またはダブルクリック）
3. ターミナルに次の順で表示される

   ```text
   Port: /dev/cu.usbmodem…
   Port opened in raw mode. Waiting for RADIO DAYS U1 ...
   Receiving https://stream.radioparadise.com/mp3-128
   Linked with the Cardputer (@RD HELLO U1). Sending audio.
   Cardputer> [U1] host linked (RDSYNC)
   Cardputer> [U1] playing
   Sent 0.2 MB in total, 16.0 KB/s     ← 10秒ごと
   ```

4. Cardputerの画面が「LINK: relay running」→「BUFFERING」→「**PLAYING**」になり、音が出る
5. 音量は `;`（上げる）・`.`（下げる）、ミュートは `M`
6. **止めるとき**：ターミナルで `Control` キーを押しながら `C`、またはターミナルの窓を閉じる。Cardputerは5秒ほどで待機に戻る

### 手順3：10分間の連続再生

10分以上再生して、Cardputerの画面の数字を確かめる。

| 表示 | 期待する値 |
| --- | --- |
| `underruns` | **0のまま**（増えると、音が途切れたか、途切れかけた） |
| `restarts` | 0のまま |
| `… B/s` | 約16,000（128kbps） |
| `queue` | 0〜15,000の間を上下する |
| `heap … min …` | 「min」が下がり続けない |
| ターミナルの `KB/s` | 約16 |

## 5. 知らせてほしいこと

- 手順1の結果（リセットされたか）
- 音が出たか。音の途切れや雑音はあったか
- 10分後の `underruns`、`restarts`、`B/s`、`heap min` の値
- ターミナルに出たエラー（あれば）

## 6. 職場での注意

- このスクリプトは、Macのネットワーク設定を変えない。インターネット共有も使わない。Macが通常どおりRadio Paradiseを受信するだけ
- 中継している間は、`caffeinate` でMacのスリープを止める（スクリプトを止めると元に戻る）
- 社内プロキシが必要な環境では、ターミナルで `export https_proxy=http://（プロキシのアドレス）:（ポート）` を設定してから実行する（U0ではプロキシなしで受信できた）
- USB機器の接続と、業務中の音声の利用は、職場の規則に従う

## 7. 未確認事項

| 項目 | 内容 |
| --- | --- |
| 実機での再生 | 未確認。音が出ることは、実機で確かめるまで「成功」としない |
| ポートを開いたときのリセット | 未確認（手順1で確かめる） |
| USBの実際の速さ | シミュレーションでは64KB/秒まで問題なし。実機のHWCDCの速さは未確認 |
| 1バイトずつのキュー | ArduinoのHWCDCは、1バイトずつFreeRTOSのキューに出し入れする。16KB/秒なら負荷は小さいと考えるが、実測していない |
| ターミナルのダブルクリック起動 | ダウンロードしたファイルは初回に警告が出る（右クリック→「開く」）。「perl＋ドラッグ」なら警告なしで動く |
| 局の数 | U1は1局だけ（スクリプトの中に固定）。選局は次の段階（U2） |

## 8. 実機試験の結果（2026-10-21、作者）

**U1は実機で動作した。** 職場のMac（有線LAN）からUSB経由でRadio Paradiseを再生できた。

| 項目 | 結果 | 判定 |
| --- | --- | --- |
| 再生 | Macの有線LANで受信したRadio Paradiseを、USB経由でCardputerのスピーカーから再生できた | 成功 |
| 連続再生 | 10分以上 | 成功（目標の10分以上） |
| `underruns` | 0 | 途切れなし |
| `restarts` | 0 | デコーダーの再起動なし |
| 転送速度 | 約15.6 KB/秒 | 128kbps（16 KB/秒）の再生に見合った速さ |
| `heap min` | 234,272 B | 十分な空きメモリ（Wi-Fiを使わない版） |
| ポートを開いたときのリセット | **リセットされなかった** | 手順1の確認どおり |
| 音の品質 | 聴いた限り、気になる音飛びや雑音はなかった | 良好 |

これにより、次のことを実機で確かめた。

- HWCDCのクレジット方式で、データを失わずに送れる
- macOS標準のPerlとcurlだけで中継できる
- USB設定（Hardware CDC and JTAG）を変えずに済む
- Macでシリアルポートを開いても、Cardputerはリセットされない

第7節の未確認事項のうち、「実機での再生」「ポートを開いたときのリセット」「USBの実際の速さ（128kbpsに対して十分）」は解消した。
