- 作成日：2026-10-22
- 状態：**調査と提案だけ**。コード、`stations.h`、USB中継、READMEは変えていない
- 注記（2026-10-22、公開準備）：**U8（19 Location、`LOCATION_COUNT == 19`、中継U4）の時点の資料**。U10（7 Location、中継 `RadioDaysRelay_U9.command`）での手順は README の「放送局を追加・変更する」を参照
- 目的：標準の収録国を減らしても（[location-selection-review.md](location-selection-review.md)）、利用者が自分の国や好きな局を加えられるように、今の作りで必要な作業を整理する
- 調べた版：U8（`firmware/RadioDays_U8/stations.h`、`RadioDays_U8.ino`、`radiodays_link.h`）、USB中継 `tools/usb-relay/RadioDaysRelay_U4.command`

## 1. 今の放送局のデータの構造

局の表は **`stations.h` にだけある**（ファームウェアに組み込み。変えたらビルドし直す）。

```cpp
struct Station {
    const char* name;  // 画面の局名（ASCII、19文字まで）
    const char* city;  // 局の都市（記録用。今の画面には出ない）
    const char* url;   // 配信のURL（http:// のMP3）
    int freq;          // ダイヤルの位置（決まった式で計算した値。表示はしない）
};

struct Location {
    const char* name;      // Location名（大文字・ASCII、7文字まで、重複なし）
    const char* city;      // Location画面に出る都市名（時計と空の都市）
    float lat, lon;        // 地球儀の印と、昼夜（太陽の高度）の計算
    bool hasMarker;        // 地球儀に印を出すか（WORLDはfalse）
    int freqMin, freqMax;  // ダイヤルの端（800 と RD_DIAL_MAX(局の表)）
    const Station* stations;
    int count;             // RD_COUNT(局の表)
    const char* tz;        // POSIXのタイムゾーン（夏時間を含む）
};
```

- Locationごとに `static constexpr Station STATIONS_xxx[] = { … };` の表があり、最後の `LOCATIONS[]` に1行ずつ並ぶ
- **ビルドの時の検査**（`static_assert`）：局の位置が式どおり、名前の長さ、Location名の重複、Locationの数が19で最初の5つが JAPAN・USA・UK・FRANCE・WORLD であること。間違えるとビルドが止まる（実機に書き込む前に気づける）

## 2. 放送局を1局追加・削除・変更する

### 2.1 変更する箇所

| 作業 | 変更する箇所 |
| --- | --- |
| 局のURL・名前を変える | その局の1行だけ（`freq` はそのまま） |
| 局を加える・外す・並べ替える | ① その国の `STATIONS_xxx[]` の行、② **その国のすべての局の `freq` を計算し直す**（第4節の表）。`LOCATIONS[]` の行は変えなくてよい（局数とダイヤルの端は自動） |
| USB中継で聴く場合 | 新しいホスト・ポートを中継の許可の一覧に加える（第5.3節） |

### 2.2 例（UKに1局加えて6局にする）

```cpp
static constexpr Station STATIONS_UK[] = {
    {"BBC World Service", "London", "http://stream.live.vc.bbcmedia.co.uk/bbc_world_service", 810},
    {"Heart London",      "London", "http://media-ice.musicradio.com/HeartLondonMP3", 830},
    // … 6局なら 810, 830, 850, 870, 890, 910
};
```

## 3. Locationを追加・削除する

| 作業 | 変更する箇所 |
| --- | --- |
| 追加 | ① `STATIONS_xxx[]` を作る、② `LOCATIONS[]` の**WORLDより後ろ**に1行（名前、都市、緯度・経度、`true`、`800`、`RD_DIAL_MAX(STATIONS_xxx)`、`STATIONS_xxx`、`RD_COUNT(STATIONS_xxx)`、タイムゾーン）、③ タイムゾーンの `#define`（同じものがなければ）、④ `static_assert(LOCATION_COUNT == 19 …)` の数を直す |
| 削除 | ① `LOCATIONS[]` の行と局の表を消す、② `LOCATION_COUNT == 19` の数を直す。最初の5つ（JAPAN、USA、UK、FRANCE、WORLD）は消さない（今の作りの約束） |
| 起動時の既定 | `LOCATION_DEFAULT`（今は1＝USA）。Locationを並べ替えたら確かめる |

**保存との関係**：本体はLocationを「番号と名前」で保存し、起動時に名前で探す（`savedLocationIndex()`）。名前を変える・消すと、保存していたLocationが見つからず、既定のLocationで始まる（壊れはしない）。

**画面**：Location画面は5行ずつの一覧（`LOC_LIST_ROWS = 5`）で、数が増えると次のページに続く。地球儀の印は緯度・経度から自動で描かれる。時計と昼夜はLocationの `city`・`lat`・`lon`・`tz` で決まる。

## 4. 局数が変わったときのダイヤル

局数からダイヤルの1周の長さが自動で決まり（目盛りの周期30段＝60 pxの整数倍、1局あたり約20段）、局は1周に等しい間隔で並ぶ。**`freq` は次の値にする**（`800 + (2i+1) × 1周 ÷ (2 × 局数)` の整数部分）。

| 局数 | 1周（段 / px） | 各局の `freq` | 局の間隔（段） |
| --- | --- | --- | --- |
| 1 | 30 / 60 | 815 | ― |
| 2 | 30 / 60 | 807, 822 | 15 |
| 3 | 60 / 120 | 810, 830, 850 | 20 |
| 4 | 90 / 180 | 811, 833, 856, 878 | 22.5 |
| 5 | 90 / 180 | 809, 827, 845, 863, 881 | 18 |
| 6 | 120 / 240 | 810, 830, 850, 870, 890, 910 | 20 |
| 7 | 150 / 300 | 810, 832, 853, 875, 896, 917, 939 | 約21 |
| 8 | 150 / 300 | 809, 828, 846, 865, 884, 903, 921, 940 | 約19 |
| 9 | 180 / 360 | 810, 830, 850, 870, 890, 910, 930, 950, 970 | 20 |
| 10 | 210 / 420 | 810, 831, 852, 873, 894, 915, 936, 957, 978, 999 | 21 |

- 1局あたりの間隔はほぼ同じなので、局が増えるとダイヤルが長くなる（AUTOでの移動の時間は局の間で同じ、約0.4秒）
- 8局以上・2局以下のダイヤルは、Macの試験・実機とも**未確認**（今の85局は3〜7局）
- `freq` は昔の「0.1 MHz単位」の名残の名前で、本当の周波数ではない。画面にも出ない

## 5. ストリームのURLと再生方式の制約

### 5.1 RADIO DAYSが再生できるもの

| 条件 | 内容 |
| --- | --- |
| 方式 | **`http://` のMP3だけ**（ESP8266AudioのMP3の復号）。`https://`、HLS（`.m3u8`）、AAC、Ogg、プレイリスト（`.m3u`、`.pls`）は不可 |
| ビットレート | 作者の方針で **192k以下**（U4で256〜320kの局を除いた）。256k以上が実機で鳴るかは未確認 |
| 標本化の周波数 | 今の局は22.05〜48kHz（MPEG-1・2のLayer III）。48kHzや低いビットレートの局の多くは実機で未確認 |
| 応答 | `HTTP/1.x 200`、`ICY 200`（一部のSHOUTcast）を受け付ける |
| 転送（リダイレクト） | Wi-Fiでは再生の部品が自分で転送をたどる。USB中継では、転送先も許可の一覧と照合する（`http://` のまま、3回まで） |
| URLの長さ | USB中継では300文字まで（中継の `MAX_URL`。本体の送る行は約380文字までだが、中継が300文字を超えるURLを断る） |
| 名前 | 局名・Location名はASCIIだけ（内蔵の字体にアクセント記号や日本語がない）。「Chérie」→「Cherie」 |

### 5.2 局を探すとき
- 局の公式サイトが案内するURLを優先する。局の一覧サービス（Radio Browserなど）のURLは公式と限らない
- `https://` のURLしかない局でも、同じホストの `http://` が使えることがある（使えない場合も多い）
- **利用条件**：配信の利用条件を確かめる。技術的に再生できることと、利用が認められていることは別

### 5.3 USB中継（Mac）を使う場合
- 中継は、**許可した「ホスト:ポート」のURLだけ**を受信する（安全のため）。今の許可の一覧は中継のスクリプトに組み込まれている（U4の局のホスト）
- 加える方法：中継の `.command` と同じフォルダに `allowed_hosts.txt` を置き、1行に1つ `host:port`、転送先が毎回変わるものは `redirect *.example.com:80` と書く（このファイルがあると、組み込みの一覧の代わりにこのファイルだけが使われる。**今ある局のホストも書く必要がある**）
- 中継には確かめる機能がある：`perl RadioDaysRelay_U4.command --check-url <URL>`（URLが許可されるか）、`--check-redirect <URL>`（転送先が許可されるか）。READMEで紹介するとよい
- IPアドレスのURLは中継が断る。Wi-Fiで聴く場合にIPアドレスのURLが使えるかは**未確認**

## 6. 初心者が間違えやすい点

1. **`freq` の計算し直しを忘れる**（局を加えたのに、ほかの局の値をそのままにする）→ ビルドで「(U6) a ring of whole tick periods; stations evenly round the ring」と止まる
2. `https://` や `.m3u8`、`.pls` のURLを入れる → ビルドは通るが鳴らない（雑音のまま、または次の局へ）
3. 局名が20文字以上、アクセント記号を含む、Location名が8文字以上 → ビルドで止まる、または文字が出ない
4. `LOCATION_COUNT == 19` を直し忘れる → ビルドで止まる
5. 新しいLocationをWORLDより前に入れる・最初の5つの名前を変える → ビルドで止まる（保存の記録の互換のため）
6. カンマ・波かっこ・引用符の抜け → ビルドの文法の誤り
7. USB中継の許可の一覧に加え忘れる → USBでだけ鳴らない（Wi-Fiでは鳴る）
8. ビルドの設定（ボード、USB CDC On Boot など）の違い、アプリの大きさが0x150000（1,376,256 B）を超える → U8の残りは1,856 Bしかない。**局を増やすと文字列の分だけ大きくなる**（大きさはビルドして確かめる）
9. タイムゾーンの書き方の誤り → 時計がずれる（ビルドでは見つからない）

## 8. 改造しやすくするための改善案（実装はしない）

| 案 | 内容 | 効果 | 注意 |
| --- | --- | --- | --- |
| A：`freq` を自動で計算する | 局の行から `freq` をなくし、表の何番目かから `rdPos()` で決める | 間違えやすい点1がなくなる。局を加えるのは1行だけになる | 内部の作りの変更（新しい版で）。大きさの変化はビルドして測る |
| B：局の表を別のファイルに分ける | `stations.h`（仕組み）と `stations_user.h`（局の表）に分ける | 利用者が触るファイルが小さく、はっきりする | |
| C：中継の許可の一覧を局の表から作る小さなスクリプト | `stations.h` のURLから `allowed_hosts.txt` を作る | 間違えやすい点7がなくなる | 転送先は別に調べる必要 |
| D：URLを確かめるスクリプト | Macで各URLに接続し、`http://`・MP3・ビットレート・転送先を表にする（今回の調査で使った確認の方法） | 鳴らないURLをビルド前に見つけられる | 実機の確認の代わりにはならない |
