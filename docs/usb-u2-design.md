# USB接続 U2：複数局の選局（設計案）

- 作成日：2026-10-21
- 状態：**設計案。実装はまだ始めていない**
- **決定（2026-10-21）**：第10節の項目は作者が決定した。U2aの確定用の設計は [usb-u2a-design.md](usb-u2a-design.md)
- 前提：U1が実機で動作した（[usb-u1.md](usb-u1.md) 第8節）。クレジット方式、Perlとcurlでの中継、ポートを開いてもリセットされないこと、128kbpsに対して十分な速さを確認済み

---

## 1. U2の目標

- USB中継でも、**Stage 3-3と同じ操作**（AUTO／MANUAL、ノイズ、Location、地球儀、メーター）で、複数局を選局できる
- 選局、音量、Locationの変更は、今までどおりCardputerで行う。Mac側は中継するだけ
- Wi-Fiの環境では、今までどおりCardputer単独で動く

## 2. どの版をもとにするか（提案）

**Stage 3-3をもとにして、新しいフォルダ（例：`firmware/RadioDays_U2/`）で作る。**

- 選局・Location・地球儀などの仕組みは、すでに3-3にある。U2で加えるのは「音の入口」をWi-FiとUSBのどちらにするかの切り替えだけ
- U1の「シリアルから読む音声の入口」とクレジットの処理を、ほぼそのまま移す
- 大きさの見込み：3-3（1,355,184 B）＋数KB。0x150000（1,376,256 B）の残りは約17KBになる【推測】。この先の段階では超える可能性がある（第9節）

## 3. やり取りの拡張（U1からの変更）

**新しく「選局番号（seq）」を付け、局を変えるたびに1つ増やす。** 前の局のデータと新しい局のデータを、この番号で区別する。

| 方向 | U1 | U2 |
| --- | --- | --- |
| Cardputer → Mac | `@RD HELLO U1` | `@RD HELLO U2`（つながるまで2秒ごと） |
| Cardputer → Mac | （なし） | `@RD TUNE <seq> <URL>`：この局を受信して |
| Cardputer → Mac | （なし） | `@RD STOP <seq>`：受信を止めて（MANUALの局間ノイズのときなど） |
| Cardputer → Mac | `@RD MORE <n>` | `@RD MORE <seq> <n>`：この局のデータを、あとnバイト送って |
| Mac → Cardputer | `RDSYNC` の1行 | `RDHOST 2` の1行（中継が動いている合図。TUNEより前） |
| Mac → Cardputer | （なし） | `RDSYNC <seq>` の1行：ここから先は局seqのデータ |

### 局を変えるときの流れ

```text
Cardputer: 再生を止める → seq を1増やす → "@RD TUNE 8 http://..." を送る
           → 受信したデータを捨てながら "RDSYNC 8" を探す
Mac:       今の curl を止める → "RDSYNC 8" を送る → 新しい curl を始める
           → "@RD MORE 8 …" の分だけ送る（seqの違うMOREは無視する）
Cardputer: "RDSYNC 8" を見つけたら、クレジットを0から数え直し、MOREを出す → 貯めてから再生
```

- **前の局の残りが混ざらない**：区切りの前のデータは、すべて捨てる
- **あふれない**：前の局に出したクレジットは、多くても受信キューの大きさまで。その分は捨てながら読むので、キューはあふれない
- **速く回したとき**：Stage 2-2と同じく、ダイヤルが0.35秒止まってから1回だけTUNEを送る。もしTUNEが続いても、最後のseqの区切りだけを待つ
- 区切りの文字列がMP3の中に偶然現れる確率は、ごく小さい【推測】。区切りは、区切りを探している間しか調べない

## 4. URLの扱いと安全

| 項目 | 設計 |
| --- | --- |
| URLの出どころ | Cardputerの `stations.h`（今の一覧をそのまま使う）。Mac側に局の一覧を持たないので、二重管理にならない |
| Macでの確認 | `http://` か `https://` で始まり、使える文字だけでできていて、300文字以内であることを確かめる。`-` で始まる値は受け付けない |
| 渡し方 | シェルを通さず、1つの引数として `curl` に渡す（U1と同じ） |
| 追加の制限（任意） | Mac側に「受信してよいホストの一覧」を置き、それ以外を拒否する。職場で使うなら、こちらのほうが安心 |
| HTTPSの局 | Macの `curl` が受信するので、HTTPSの局も中継できる。ただし、Wi-Fi単独では再生できないので、**「USBのときだけ選べる局」にするかは判断が必要**（第10節） |

## 5. 音の入口の切り替え（Wi-FiとUSB）

| 状態 | 動き |
| --- | --- |
| 中継がつながっている（`RDHOST` を受け取った） | **USBから再生する**。Wi-Fiは使わない |
| 中継がない、Wi-Fiがある | 今までどおりWi-Fiで再生する |
| どちらもない | 「WAITING FOR WI-FI / USB」と表示する。MANUALのノイズは鳴る（ネットワーク不要） |
| 再生中にUSBが抜けた | 5秒データが来なければ、Wi-Fiがあれば同じ局をWi-Fiで再生し直す。なければ待機する |
| 再生中に中継が始まった | 今の局を、USBで再生し直す（両方あるときにどちらを優先するかは第10節） |

**再生用タスクへの変更は、局を開く部分だけにする。**

- 今の `new AudioFileSourceICYStream(url)` の代わりに、USBなら「シリアルの入口＋TUNE」にする
- 32KBのバッファー、デコーダー、ノイズ、メーター、`stopStream()` の流れはそのまま使う
- 「再生してよい」の条件を「Wi-Fiにつながっている」から「Wi-FiかUSBのどちらかが使える」に広げる

## 6. Mac側のスクリプト（`RadioDaysRelay_U2.command`）

| 項目 | 内容 |
| --- | --- |
| 起動 | U1と同じ（ダブルクリック、または「perl＋ドラッグ」） |
| ポート | 見つからない、または抜けたときは、2秒ごとに探し直す（終了しない）。抜き差ししてもスクリプトを起動し直さなくてよい |
| TUNE | 今の `curl` を止め、区切りを送り、新しい `curl` を始める |
| STOP | `curl` を止める（通信量を節約） |
| MORE | seqが今の局と同じものだけを数える |
| 局が切れたとき | 同じ局に自動でつなぎ直す（区切りは送らない。MP3デコーダーが自分で同期し直す） |
| 表示 | 今の局、送った量、KB/秒、Cardputerの記録 |
| スリープ防止 | `caffeinate`（U1と同じ） |

## 7. 時計と空（USBのとき）

Wi-FiがないとNTPが使えないので、時計は `--:--`、空の窓も空のままになる。

**提案**：Macが `RDHOST 2` と一緒に、今の時刻を `RDTIME <UTCの秒数>` で送る。Cardputerはそれで時計を合わせ、「時刻の出どころ：Mac」として扱う。

- Macの時計は、普段からネットで合わせてあるのが普通【一般】
- これで、USBだけでも時計、月、昼夜の空が動く
- 実装はU3でもよい

## 8. 画面

- 最下行のWi-Fiの欄に「USB」と表示する（例：`USB 15.6KB/s`）
- 起動画面で中継が見つかれば、Wi-Fiの設定がなくても再生を始める（今は、Wi-Fiの設定がないとWi-Fi設定の画面に進む）

## 9. 大きさとメモリ

| 項目 | 見込み |
| --- | --- |
| アプリの大きさ | 3-3＋数KB。0x150000に収まる見込みだが、残りは約17KB【推測】。この先で超えた場合、Launcherはアプリに合わせた領域を作るので導入はできる（設計書 3.5.1節）。ただし、「0x150000以内」という条件を続けるかは判断が必要 |
| RAM | 受信キュー16KBが増える。Wi-Fiを使わないUSBのときは、U1のheap min（234 KB）から見て余裕がある。Wi-FiとUSBの両方を使う場合は、実測が必要 |

## 10. 決めていただきたいこと

1. **もとにする版**：Stage 3-3をもとにする（推奨）か、U1のような単独の試験版で、先に複数局だけを試すか
2. **両方あるときの優先**：中継とWi-Fiの両方が使えるとき、USBを優先する（推奨：中継を起動したということは、USBで聴きたいという意思表示と考えられる）か、Wi-Fiを優先するか
3. **HTTPSの局**：USB中継のときだけ選べる局を作るか（今の局の一覧はすべてHTTPなので、すぐには必要ない）
4. **URLの扱い**：Cardputerから送る（推奨：一覧が1つで済む）か、Mac側の一覧に限るか。職場向けに、Mac側で「受信してよいホストの一覧」を使うか
5. **時計（RDTIME）**：U2に含めるか、U3に回すか

## 11. 段階的な開発計画（案）

| 段階 | 内容 | 判定 |
| --- | --- | --- |
| **U2a** | やり取りの拡張（seq、TUNE、STOP、RDSYNC seq、RDHOST）。Mac用スクリプトU2。Stage 3-3のコピーに、USBの音の入口を入れる（USBがあればUSBを使う） | AUTO／MANUAL、Locationの全局をUSBで選局できる。速く選局しても前の局が混ざらない |
| **U2b** | Wi-FiとUSBの自動切り替え、抜き差しからの復帰、画面の「USB」表示 | 抜き差しでフリーズしない。Wi-Fiだけの環境で今までどおり動く |
| **U3** | Macからの時刻（RDTIME）、起動画面の改善、（任意）ログイン時の自動待機 | USBだけで時計と空が動く |

各段階で、U1と同じ仮想シリアルポートでのシミュレーションを広げて、事前に確かめる。

- 選局の連続、速い選局、STOP→TUNE、前の局のデータが混ざらないこと、抜き差し
- U1のテスト（捨てられたデータ0、データの一致）も続けて行う

そのうえで、実機で確かめる。
